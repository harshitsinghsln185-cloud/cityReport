## 4. Current System Inspection & Architecture Audit

### 4.1 `Category` Model (`server/src/models/Category.js`)
* **Fields:** `name` (String, required, unique), `slug` (String, required, unique, indexed), `description` (String, required), `baseFeePaise` (Integer, required), `isActive` (Boolean, default: true), `icon` (String, default: 'alert-circle').
* **Observation:** Currently lacks an embedded `subCategories` array. We will add `subCategories: [{ name, slug, order, defaultPriority, isActive }]` and an `order` integer field to the category root.

### 4.2 Category Seeding & Admin Management
* **Baseline Seed:** `server/src/seed/seedDefaults.js` defines 6 initial categories (`road-damage`, `water-supply`, `drainage`, `streetlight-electricity`, `garbage`, `other`).
* **Admin Category Controller:** `server/src/controllers/category.controller.js` supports `getActiveCategories`, `getAdminCategories`, `createCategory`, `updateCategory`, and `toggleCategoryStatus`.
* **Missing Endpoints:** Currently missing public detail endpoint `GET /api/categories/:slug`.

### 4.3 `Issue` Model (`server/src/models/Issue.js`)
* **Category Association:** `category: { type: ObjectId, ref: 'Category', required: true, index: true }`.
* **Missing Fields:** Currently lacks `subCategory` (slug string) and `subCategoryName` (snapshot string).

### 4.4 Report Form (`client/src/pages/user/ReportIssue.tsx`)
* **Current UI:** Wizard Step 1 uses a single `<select>` dropdown populated from `categoryService.getActiveCategories()`.
* **State Management:** `formData.category` stores the selected Category `_id`.
* **Query Params:** Reads `searchParams.get('category')` by matching `_id` or name substring. Currently ignores `sub` query parameter.

### 4.5 `ProtectedRoute.tsx` & Login Redirect Behavior
* **Route Guard:** `client/src/components/ProtectedRoute.tsx` redirects unauthenticated users using `<Navigate to="/login" state={{ from: location }} replace />`.
* **Redirect Bug Found:** `client/src/pages/auth/Login.tsx` reads `location.state?.from?.pathname` and navigates to `from`. **It currently drops `location.search`!**
  * *Example:* When sent from `/user/report-issue?category=roads-transportation&sub=road-potholes`, the query parameters are currently stripped upon redirect after login.
  * *Fix Required in V2:* Update `Login.tsx` to preserve `from.search` (i.e., `${from.pathname}${from.search || ''}`).

### 4.6 Services Page & `ServiceCard.tsx`
* **Services Page (`client/src/pages/public/Services.tsx`):** Lists categories with client-side search and category tagging.
* **ServiceCard (`client/src/components/public/ServiceCard.tsx`):** Currently hardcodes Unsplash images using regex keyword matches and links directly to `/user/report-issue?category=<id>`.
* *Fix Required in V5:* Card must link to `/services/:categorySlug`, display sub-issue count, and load local responsive optimized civic images.

### 4.7 AI Severity & Chatbot Category Usage
* **AI Service (`server/src/services/aiService.js`):** `evaluateSeverity(categoryName, description)` provides Gemini-based municipal hazard evaluation with rule severity fallback.
* **Chatbot Service (`server/src/services/chatbotService.js`):** Dynamically queries `Category.find({ isActive: true })` from MongoDB to present category quick replies.
* *Compatibility Guarantee:* Because categories remain in the `categories` collection with `name` and `isActive`, the chatbot continues working seamlessly.
